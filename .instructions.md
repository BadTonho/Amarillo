# Amarillo MCP Tools Configuration

## MCP Server Configuration

The Amarillo project provides MCP (Model Context Protocol) tools for Studio automation and project management.

### Available Tools

The following MCP tools are available through the Amarillo daemon:

- **health** - Returns daemon, workspace, and active sessions status
- **list_projects** - Lists all discovered Argon projects in the workspace
- **set_active_project** - Sets the default project for new sessions
- **get_tree** - Returns the current Studio tree for a connected session
- **get_selection** - Returns the current Studio selection
- **inspect_instance** - Searches for a node path in the Studio tree
- **run_code** - Executes Luau code in the connected Studio; privileged and may require plugin confirmation
- **push_changes** - Captures the current Studio state and saves to disk
- **pull_changes** - Reads local project state and applies it to the Studio
- **start_playtest** - Starts a playtest session
- **stop_playtest** - Stops a playtest session
- **get_properties** - Returns all readable properties of an instance
- **get_instance_info** - Returns detailed information about an instance
- **get_descendants** - Lists all descendants of an instance with filtering
- **search_instances** - Searches for instances by name or class
- **get_services** - Lists all services in the game
- **get_output_log** - Retrieves output log entries
- **modify_property** - Modifies a property or attribute of an instance

## How to Use

To use these tools, you need to:

1. **Start the MCP proxy** (if not already running):
   - Run task: "Amarillo Dev: Start Example Daemon"
   - Or manually: run `npm.cmd run build` first, then `node src/mcp-proxy/index.js --workspace . --port 8323`

2. **Request the tools** - I can now use any of the above tools by:
   - Asking me directly to perform Studio operations
   - Using specific tool names in requests
   - Providing session IDs from active Studio connections

## HTTP Fallback Auth

If an AI client tests the HTTP fallback manually, protected routes such as `GET /mcp/status`, `GET /mcp/tools`, `POST /mcp/probe`, and `POST /mcp/call` require the bridge token.

Use one of these headers:

```text
X-Amarillo-Bridge-Token: <bridge token>
Authorization: Bearer <bridge token>
```

The token is written into the generated `.vscode/mcp.json` proxy args when Amarillo configures MCP for the workspace.

For a quick local check, run:

```powershell
npm.cmd run diagnose:mcp -- --workspace .
```

# Amarillo Bridge

VS Code extension that installs the Amarillo plugin into Roblox Studio and manages the local bridge without depending on this repository folder.

It also adds its own activity bar entry in VS Code so you can control the bridge more easily.
The sidebar shows the active Roblox Studio session and the send or receive sync commands.
The MCP generated by the extension uses a `stdio -> HTTP` proxy so it can reuse the bridge that is already running instead of opening a second daemon on the same port.

## Commands

- `Amarillo: Install Roblox Studio Plugin`
- `Amarillo: Start Bridge`
- `Amarillo: Stop Bridge`
- `Amarillo: Healthcheck`
- `Amarillo: Configure MCP for Workspace`
- `Amarillo: Open Output`
- `Amarillo: Send Files to Studio`
- `Amarillo: Receive Files from Studio`
- `Amarillo: Select Studio Session`

## Flow

1. Open your Roblox project folder in VS Code.
2. Run `Amarillo: Install Roblox Studio Plugin`.
3. Run `Amarillo: Start Bridge`.
4. In Roblox Studio, open the `Amarillo` plugin and click `Connect`.
5. Optionally run `Amarillo: Configure MCP for Workspace` to generate `mcp.json` for the current workspace.

When the workspace contains multiple `.project.json` files, you can use a base project with `abstract: true` and derived projects with `extends`. The bridge automatically resolves the correct derived project by `placeId`, and the Luau sourcemap follows the active connected session project.

## Configuration

- `amarillo.autoConnect`: if manually enabled, restores the last session when VS Code reopens. Default: off.
- `amarillo.nodePath`: Node executable used by the extension.
- `amarillo.host`: daemon host.
- `amarillo.port`: daemon port. Without a VS Code override, the extension uses `daemonPort` from `.pluginroblox.json` before falling back to `8323`.
- `amarillo.autoSyncToStudio`: automatically sends VS Code changes to Studio after the initial truth-source sync. Default: on.

If another daemon is running from a different folder on the same port, the extension shows a warning, ignores sessions from that other workspace, and keeps the current folder identity visible.
